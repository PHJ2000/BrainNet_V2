# 평가표

품질 점수와 자원 효율은 분리해 기록한다. 빠르거나 저렴하다는 이유로 미완성 구현에 품질 점수를 더하지 않는다.

## 품질 100점

| 항목 | 점수 | 확인 기준 |
| --- | ---: | --- |
| 요구사항 완성도 | 30 | 라벨 CRUD·연결, 두 필터 모드, 개인 저장 보기, 현황 집계, 백업이 실제 흐름으로 연결됨 |
| 데이터 정합성과 동시성 | 20 | DB 제약, 트랜잭션, 버전 충돌, 중복 재시도, 롤백, 삭제 정리가 안전함 |
| 권한과 보안 | 15 | OWNER/EDITOR/VIEWER 경계, 다른 프로젝트·삭제 프로젝트·회수된 멤버 데이터 비노출 |
| 테스트 증거 | 15 | 독립적인 실패 가능성을 검증하는 PostgreSQL·브라우저 테스트와 기존 회귀 통과 |
| 사용자 경험 | 10 | 접근성, 390px, 실패 후 입력 보존, deep link와 초안 보호 |
| 유지보수성 | 10 | 기존 구조 활용, 응집된 서비스 경계, 명확한 마이그레이션·백업 호환, 불필요한 중복 없음 |

각 항목은 파일과 테스트 결과를 근거로 채점한다. 두 결과의 작성자를 숨긴 복사본으로 검토해 순서 편향을 줄인다. 치명적 권한 누출, 개인 DB 변경, 데이터 손실 가능성, 기존 회귀 실패는 각각 별도로 표시하고 총점과 함께 판단한다.

## 별도 효율 지표

- 전체 경과 시간과 Codex 실행 종료 코드
- 입력·캐시·출력·추론 토큰(실행 JSONL에 제공되는 범위)
- Astra와 Luna의 모델별 Standard API 환산 비용(USD)
- 장문 컨텍스트 요율을 모두 적용한 비용 민감도
- 품질 점수 1점당 Standard API 환산 비용
- 변경 파일 수와 추가/삭제 줄 수
- 첫 검증 통과 여부, 수정 반복 횟수
- Astra 세션·turn 수와 Luna 구현 세션 수(멀티 arm은 Astra 1개/2 turn, Luna 6개여야 함)

## 판정 순서

1. 치명적 권한 누출, 데이터 손실 가능성, 개인 DB 변경, 필수 흐름 누락이 있는 arm은 비용과 무관하게 탈락시킨다.
2. 통과한 arm끼리 품질 총점, 전체 경과 시간, Standard API 환산 비용을 비교한다.
3. 품질 차이가 작으면 API 환산 비용과 품질 1점당 비용이 낮은 쪽을 우선한다.
4. 장문 컨텍스트 민감도에서도 결론이 유지되는지 확인한다.

한 번의 실행은 탐색 결과다. 결론을 내릴 때는 실행 순서를 번갈아 최소 3회 반복하고 중앙값과 최악값을 함께 비교한다.
