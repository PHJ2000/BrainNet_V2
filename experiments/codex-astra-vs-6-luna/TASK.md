# 비교 과제: 과제 라벨과 저장된 작업 보기

BrainNet V2에 프로젝트 과제 라벨과 개인 저장 보기를 끝까지 구현한다. 기존 기능, 백업, 권한, 멱등성 계약을 깨뜨리지 않는다.

## 사용자 흐름

1. 프로젝트 OWNER는 라벨을 생성·이름 변경·색상 변경·삭제할 수 있다. 이름은 프로젝트 안에서 대소문자와 앞뒤 공백을 무시해 유일하며 1~40자다. 색상은 `slate`, `red`, `amber`, `green`, `blue`, `violet` 중 하나다. 프로젝트당 최대 30개다.
2. OWNER와 EDITOR는 과제 하나에 최대 10개 라벨을 붙이거나 뗄 수 있다. VIEWER는 조회만 가능하다. 라벨 삭제는 과제 연결만 제거하며 과제를 삭제하지 않는다.
3. 실행 보드와 내 작업함에서 라벨을 표시하고, 프로젝트 안에서는 여러 라벨 중 하나라도 포함하는 필터와 모든 라벨을 포함하는 필터를 제공한다. 필터는 서버 페이지 처리 전에 적용한다.
4. 사용자는 현재 내 작업함 조건을 개인 저장 보기로 최대 30개 보관하고 다시 적용·이름 변경·삭제할 수 있다. 보기에는 범위, 기한, 상태, 제목 검색, 막힘 여부, 라벨 ID가 들어간다. 현재 접근할 수 없는 프로젝트나 삭제된 라벨은 결과에서 안전하게 제외한다.
5. 프로젝트 현황에 라벨별 미완료 과제 수 상위 10개를 추가한다. 동률은 정규화된 라벨 이름 순이다.
6. Workspace JSON v2 백업은 라벨 정의와 과제 연결을 선택 필드로 내보내고 복원한다. 기존 v2 파일과 기존 import receipt 재전송은 그대로 동작해야 한다. 개인 저장 보기는 프로젝트 백업에 포함하지 않는다.

## 데이터와 API 계약

- PostgreSQL 제약과 인덱스로 프로젝트별 정규화 이름 중복, 과제-라벨 연결 중복, 개수 경계를 가능한 범위에서 보호한다.
- 새 마이그레이션은 현재 `b922004`에서 전진·후진 가능해야 한다.
- 요청 검증 실패, 권한 실패, 버전 충돌, 한도 초과는 부분 저장 없이 끝난다.
- 라벨 연결 갱신은 과제의 `expected_version`을 검사하고 성공 시 과제 버전을 1 올린다.
- 생성형 요청에는 기존 프로젝트 패턴에 맞는 멱등성 키 또는 클라이언트 생성 UUID를 사용한다. 같은 요청 재전송은 중복을 만들지 않고, 같은 키의 다른 본문은 거절한다.
- 목록 응답과 백업 형식은 기존 클라이언트가 새 필드를 무시해도 동작하도록 추가 필드로 확장한다.

## 화면과 복구

- 기존 흰 작업 화면과 남색 강조를 유지한다. 색상만으로 상태를 전달하지 않는다.
- 키보드 조작, 명시적 label, 390px 가로폭 무넘침을 지킨다.
- 저장 실패 시 사용자가 입력과 선택을 잃지 않고 같은 내용으로 재시도할 수 있다.
- 정확한 과제 deep link와 다른 과제의 로컬 초안 보호를 유지한다.

## 검증과 완료 조건

- 단위·PostgreSQL·브라우저 테스트에 권한, 정규화 중복, 동시 생성, 버전 충돌, 일괄 롤백, 백업 하위 호환, 삭제 정리, 필터 페이지 처리, 모바일·키보드 흐름을 포함한다.
- Ruff, Python compile, Alembic check, TypeScript, ESLint, 프런트 단위 테스트와 변경 기능 브라우저 검사를 통과시킨다.
- 개인 `brainnet-local` DB를 테스트에 사용하거나 변경하지 않는다. 필요하면 `brainnet-next-validation` 전용 DB만 사용한다.
- 커밋·푸시·외부 배포는 하지 않는다. 구현과 로컬 검증 결과를 최종 답변에 정확히 보고한다.
