# Spring 소유 작업 공간

## 구현 경계

이 구성은 `main`의 Spring 백엔드에 `feat/brainnet-workspace-v3`의 화면과 작업 공간 기능을 통합한다. V3는 별도 제품 버전이 아니라 해당 기능 브랜치의 이름이다.

| 책임 | 실행 주체 |
| --- | --- |
| 인증, 프로젝트, 멤버·초대, 노드, 태그, 투표·이력 | Spring |
| 실행 과제, 체크리스트, 반복 과제, 선행 조건, 개인 작업 목록·프로젝트 요약 | Spring |
| 토론·답글·멘션 알림, 지식 검색·북마크·연결, 개인 초안·검색·템플릿 | Spring |
| JSON v1/v2 가져오기·내보내기, Markdown, 휴지통, 노드 작업 복구 | Spring |
| AI 노드 생성, 영속 제안 큐·예산·취소·채택·외부 provider 호출 | Spring |
| DB 구조 생성 및 기존 DB 이전 | Spring/Flyway |
| WebSocket 인증·권한 재확인, outbox 발행·수신·전달 | Python relay |

nginx는 `/projects/{id}/ws`만 relay로 전달한다. 나머지 API는 Spring으로 고정한다. Python에는 업무 HTTP 라우터를 등록하지 않으며 API 문서도 공개하지 않는다. relay 자체의 `/health`, `/health/events`, `/metrics`는 내부 운영 진단용이다. 공개 상태 조회는 Spring이 제공한다. 이전의 FastAPI REST 롤백·canary 절차는 이 구성에서 사용하지 않는다.

## 데이터와 동시성

- 새 DB는 Spring이 만들고, 기존 main(`c2f4a6b8d010`)과 Workspace(`b922004`) DB는 데이터를 유지하면서 확장한다. 중간 지원 revision은 Java migration에 명시되어 있고 알 수 없는 schema는 시작을 중단한다.
- Flyway baseline은 0, 첫 전환은 V1이다. PostgreSQL enum 확장 때문에 전환 전체가 하나의 트랜잭션은 아니다. 실행 전 기존 DB를 백업한다. 실패한 전환은 원인을 확인하고 Flyway 이력을 복구한 후 재실행해야 하며 자동 downgrade는 하지 않는다.
- Python 시작 스크립트와 이미지에서 Alembic 실행·포장을 제거했다. 기존 Alembic 소스는 과거 DB 계약 및 이력 참조용으로만 남긴다.
- 만료 후 하루가 지난 노드 생성 중복 방지 기록은 Spring이 60초마다 최대 1,000건씩 정리한다. 유효한 요청과 최근 만료된 요청은 유지한다. 발행된 outbox의 보존·정리는 relay에 남는다.
- 프로젝트 잠금과 항목 버전 검사를 사용한다. 요청 ID 재사용은 같은 사용자·내용일 때만 허용한다. 백업 가져오기는 사용자별 키를 잠가 중복 프로젝트 생성을 막는다.
- AI 작업은 DB에 저장하고 Spring worker가 잠금으로 선점한다. 외부 요청 중 JDBC 연결을 유지하지 않는다. lease가 다른 결과, 취소 후 도착한 결과는 적용하지 않는다. 오래된 RUNNING 작업은 INTERRUPTED로 전환하고 자동 재호출하지 않는다.
- AI 채택은 원본 노드의 내용·버전이 유지된 경우에만 실행한다. 최종 결과는 사용자가 확인한 후 새 과제로 저장한다.
- 읽기 전용 VIEWER는 업무 쓰기 권한이 없다. 개인 초안·북마크·검색·템플릿은 사용자별로 분리된다.

## 백업과 복구 범위

JSON v1은 지식 그래프, v2는 과제·토론·답글·AI 제안·연결·체크리스트·반복 정보를 포함한 작업 공간이다. 가져오기는 새 ID를 부여해 새 프로젝트를 생성한다. 기존 계정·권한·초대 토큰을 복제하지 않으며 담당자와 멘션은 기존 사용자에게 임의로 재연결하지 않는다. 개인 초안, 알림, 감사·작업 이력은 이식 대상이 아니다. 실행 중이던 AI 요청은 재과금 없이 중단 상태로 복원한다.

노드 작업 복구는 자신의 작업에 대해 30일간 제공한다. 그 후 관련 노드·태그·부모가 변경되면 충돌로 거부한다. 삭제된 가지의 노드와 태그 연결·내용 이력을 복구하지만, 삭제 때 해제된 과제·북마크 등 외부 참조를 되살리는 전체 프로젝트 시점 복구는 아니다. 전체 이식에는 삭제 전 작업 공간 JSON을 사용한다.

## 재현 가능한 검사

Docker, Java 25, Node.js 20 이상이 필요하다. Java 통합 검사는 Testcontainers가 별도 PostgreSQL을 만든다.

```bash
mvn -f spring/vertical-slice/pom.xml test
cd frontend
npm ci
npm run lint
npm test
npm run build
cd ..
docker compose -f deploy/spring-workspace.compose.yml up --build -d --wait --wait-timeout 240
cd frontend
npx playwright install chromium
PLAYWRIGHT_BASE_URL=http://localhost:18180 npx playwright test --reporter=line
cd ..
docker compose -f deploy/spring-workspace.compose.yml exec -T backend python /workspace/deploy/verify-spring-relay.py
```

검증 스택은 `brainnet-spring-workspace-qa`라는 별도 프로젝트·볼륨을 사용한다. 테스트용 비밀값과 모의 AI provider만 사용하며 실제 OpenAI에 요청하지 않는다. 브라우저 검사는 전용 계정을 자동 생성한다. 부담이 큰 fault/performance 검사는 명시적으로 활성화해야 하고 기본 검사의 통과로 장시간 부하 성능을 주장하지 않는다.

검증이 끝나면 이 스택만 제거할 수 있다. 아래 명령은 **검증용 데이터만** 삭제한다.

```bash
docker compose -f deploy/spring-workspace.compose.yml down -v
```

## 2026-10-13 로컬 검증 결과

- Spring: 타입 계약 전환 후 전체 검사 70개 통과. 새 DB·기존 main/Workspace DB 이전, 권한, 동시성, 백업·복구, AI 작업 상태와 만료 정리, 필드 생략/null·타입 검증·페이지 커서·내부 필드 미노출 포함.
- 프론트: production build, lint, 단위 검사 14개 통과.
- Chromium: 27개 통과, 명시 실행용 부하·장애 검사 3개 제외. 데스크톱·모바일 화면과 두 접속자 동기화 확인.
- relay 단위 검사 10개 및 실제 Spring→outbox→두 WebSocket 연결 통합 검사 통과. 멤버 접근 회수, Python 업무 HTTP 미노출, AI 요청 성공·재시도 중복 방지·취소 우선·원본 변경 후 채택 거부를 검증했다.
- 실제 OpenAI 호출, 장시간 부하 검사, 원격 CI 실행 및 운영 DB 적용은 수행하지 않았다. 검증용 앱은 개인 데이터와 분리된 스택에서 실행했다.

## 리뷰 수정과 재검증

기존 리뷰의 다섯 결함을 다음과 같이 수정했다.

| 결함 | 수정 | 회귀 검증 |
| --- | --- | --- |
| 태그 삭제·투표의 공유 잠금 승격 교착상태 | 프로젝트 배타 잠금을 먼저 잡고 권한 재검사 | 프로젝트 잠금으로 요청들을 대기시킨 뒤 동시 삭제 8건·투표 8건 모두 성공 |
| 통계 조회 후 실행 취소·삭제 미리보기 무효화 | 파생 통계를 스냅샷과 충돌 해시에서 제외; 기존 스냅샷에도 적용 | 통계 조회 전후 해시 유지·복구/삭제 성공, 실제 노드 수정은 계속 409 |
| Python 요청 해시 재시도 불일치 | Spring 기존 해시와 Python의 정렬·공백·문자 이스케이프·태스크 기본값 생략 형식을 함께 검증 | 기존 Python 모델의 고정 해시로 태스크·토론·답글·AI 제안·개인 자산 재시도; 변경한 내용/작성자는 거부; 이벤트 중복 없음 |
| V3 원문 초대 토큰 이관 누락 | 배포 전 V1 이관에 원문→해시 변환과 변환 여부 표시 추가 | main 해시는 유지, V3 원문은 변환; 수신자·만료·재사용 검사와 정상 가입; DB 해시 자체를 토큰으로 제출하면 거부 |
| UTF-16 길이 때문에 Unicode 백업 실패 | 일반 입력과 백업에 같은 코드포인트/UTF-8 검증 적용 | 이모지 8,000자 토론의 v2 왕복, v1/v2 프로젝트 이름 보존, 제한 초과 거부 |

재리뷰에서 AI 중단 작업 복구에도 프로젝트→작업 잠금 순서를 적용했고, null 멘션·원본 ID를 500 대신 422로 거부하도록 보완했다. 각각 회귀 테스트가 있다. 재검토한 잠금 순서, 권한, 요청 재사용, 트랜잭션·이벤트 경계에서 남은 차단급 결함은 발견하지 못했다.

내부 구조는 `WorkspaceRepository`의 권한·이벤트 서비스 간접 참조를 제거하고 생성자 주입으로 바꿨다. 공통 검증은 `WorkspaceInput`, 태스크 입력 계약은 `TaskFields`, 요청 해시 호환성은 `WorkspaceRequestHash`로 분리했다. 복구 코드가 백업 서비스의 공통 도우미에 의존하던 관계와 컨트롤러의 직접 SQL도 제거했다. 태스크 초안 검증은 태스크 서비스 없이 같은 입력 계약을 쓴다. 새 런타임 라이브러리는 추가하지 않았다.

변경한 Java는 google-java-format 1.37.0의 AOSP 4칸 스타일, 프론트 소스는 Prettier 3.6.2의 기본 2칸 스타일로 맞췄다. `.editorconfig`에도 들여쓰기 규칙을 남겼다. 포매터는 임시 실행했으며 앱 의존성에는 추가하지 않았다.

후속 정리에서는 작업 공간의 고정된 요청·응답 및 서비스 호출 계약도 타입으로 전환했다.

- `WorkspaceCommands`는 JSON을 한 번 검증해서 태스크·토론·답글·제안·정책·개인 자산·복구 명령으로 만든다. 잘못된 숫자/문자열 타입과 알 수 없는 필드의 기존 422 응답을 유지한다.
- `WorkspaceQueries`는 목록·개인 작업·검색·요약의 쿼리 계약을 정의한다. `WorkspaceViews`는 응답과 커서 타입을 고정해서 DB 내부 열이 자동으로 응답에 추가되지 않도록 한다.
- `TaskFields`는 저장·수정·일괄 변경·반복 생성과 백업/AI 채택에서 서비스 간에 그대로 전달된다. 수정 시 체크리스트/반복 주기의 생략과 명시적 null을 구분한다. `asMap`은 과거 요청 해시의 직렬화 호환용으로만 사용한다.
- 프로젝트 잠금 결과와 실행 취소의 저장된 응답도 명시적인 타입을 사용한다. 프로젝트 화면 DTO를 만들기 위해 JSON으로 직렬화했다가 Map으로 다시 읽던 우회도 제거했다.
- Map은 역직렬화 검증, JDBC 행 매핑, 과거 요청 해시, 버전별 백업·복구 문서를 다루는 어댑터에 남는다. 초안의 가변 JSON과 복구 스냅샷은 `JsonNode`로 응답한다. 이번 변경 범위의 고정 업무 API는 Map/Object를 요청·응답 계약으로 쓰지 않는다. 이전부터 있던 계정·태그 등의 별도 API 전체 재설계는 이번 변경에 포함하지 않는다.

타입 전환 후 재리뷰에서는 권한·잠금 순서, JSON 필드명/형식, 생략/null 처리, SQL 바인딩, 이전 요청 해시, 커서, 내부 필드 노출과 이벤트 중복을 확인했다. 회귀 테스트와 브라우저/relay 검증에서 차단급 결함은 발견하지 못했다. 큰 백업 서비스와 노드 복구 이력의 저장량은 여전히 개선 여지가 있다. 장시간 부하, 실제 AI provider, 운영 DB 적용은 위 검증 범위에 포함되지 않는다.
