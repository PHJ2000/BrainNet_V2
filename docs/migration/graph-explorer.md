# 검색, 태그 필터, 가지 접기 (#9)

`graphView.ts`가 원본 데이터에서 표시 ID/실제 일치 ID/맥락 조상/숨긴 자손 수를 계산한다. Graph의 저장 데이터와 좌표는 그대로 두며 검색 입력 또는 접기로 PATCH/DELETE를 전송하지 않는다.

- NFC 정규화, 앞뒤 공백 제거, 영문 대소문자 무시, 본문 부분 일치. IME 조합이 끝나기 전에는 검색 조건을 확정하지 않는다.
- 태그끼리 OR, 본문 조건과 태그 조건은 AND. ID 기준 중복 제거. 조상 맥락은 결과 수에서 제외한다.
- 접힌 자손도 결과 목록에 나타난다. 결과를 누르면 조상 경로만 임시로 펼치고 중앙에 선택한다. 본문/태그 조건을 해제하면 저장된 접기로 돌아간다. `전체 해제`는 접기도 초기화한다.
- 접기는 `/users/me`로 확인한 사용자 ID와 프로젝트 ID를 포함하는 로컬 저장소 키에 저장한다. 삭제된 ID는 정리한다. 서버 구조와 관계 없다.
- 숨겨진 Cytoscape 선택을 해제하고 컨텍스트 메뉴의 생성/삭제/태그 작업은 표시 ID를 다시 확인한다. 키보드 접근과 포커스 표시가 있는 검색창/결과/접기 버튼을 제공한다. 텍스트 입력의 Ctrl+Z는 가로채지 않는다.
- 노드 이벤트와 `tags.updated` 이벤트 모두 노드/태그를 재조회한다. 태그 생성/수정/삭제/연결/해제와 Outbox는 동일 트랜잭션이다. 서버 태그 OR 조회도 중복을 반환하지 않는다.

Chromium 153, Windows, i5-13600KF, RAM 64 GiB, production 빌드, 1,000개/깊이 20의 합성 노드에서 입력 확정 또는 접기 버튼부터 DOM 반영과 두 animation frame까지 각 24회 측정했다. 네트워크 대신 합성 노드 응답을 주입한 화면 계산/그리기 측정이다.

| 항목 | 첫 측정 | 스타일 갱신 수정 후 |
|---|---:|---:|
| 검색 p95 | 272.3 ms | 220.5 ms |
| 접기/펼치기 p95 | 264.4 ms | 174.9 ms |
| 초기 화면 로딩 | 396 ms | 382 ms |

검색 300ms/접기 200ms 목표를 통과했다. 수정 후 검색 최대값은 505.2ms였으므로 모든 단일 입력이 목표 이내였다는 의미는 아니다. 노드 라벨/스타일이 바뀔 때만 재적용하여 불필요한 글자 크기 및 연결선 계산을 줄였다. 결과 목록은 40개씩 더 표시한다. 이 측정은 5,000개에서의 UI 성능 보장이 아니다.

최종 전체 브라우저 검증에서도 각 24회 측정했다. 검색 p95 **194.3 ms**, 접기/펼치기 p95 **169.4 ms**, 초기 로딩 **548 ms**였다. [최종 원시 자료](../../experiments/runtime-nodes/results/next-version-2026-09-13/display-performance-final.json)에 전체 표본과 환경을 남겼다.
