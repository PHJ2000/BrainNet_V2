# BrainNet V2 — 7일 개선 계획

작성일: 2026-09-22 · 계획 기간: 2026-09-22~09-28 또는 착수일부터 7일

목표: 초대·인증·실시간 연결의 보안 문제를 먼저 정리하고, 사용자가 실패와 저장 상태를 알 수 있는 기능을 추가한다. 기존 기능의 회귀 검증까지 포함한다.

| 기존 미커밋 작업 | 추적 파일 수정 27개, 미추적 파일 14개. 이 계획서 생성 전 수치 |

원격 참조를 최신화했으며 현재 작업 트리는 이미 원격 최신 코드를 포함한다. 따라서 pull/merge/reset 없이 기존 작업을 보존했다. 이번에는 계획 문서만 추가하며 소스 수정·커밋·push·배포는 하지 않는다.

분석은 **원격 main의 문제**, **로컬 커밋으로 구현된 기능**, **미커밋 수정**, **새로 필요한 작업**을 구분한다. 원격 main만 다시 체크아웃하면 현재 로컬의 기능·수정이 빠지므로 이를 개선 기준으로 되돌리지 않는다.

## 2. 이미 구현되어 있어 중복 개발하지 않을 항목

- 로컬 커밋: 노드 작업 이력과 되돌리기, 텍스트·태그 검색, 가지 접기, Markdown 내보내기, JSON 백업·가져오기.
- 미커밋: 계정에 귀속되는 7일·일회용 초대, 삭제 프로젝트 접근 차단 보완, 프로젝트 설정·참여 UI, 로그인 만료 처리, 그래프 데이터/액션 분리, 입력 검증과 화면 전환 중 요청 처리 보완.
- 현재 코드: Outbox → PostgreSQL NOTIFY/LISTEN → WebSocket 전달, 재연결·주기적 재조회, 노드 생성 동시 처리 제한, 멱등성, 버전 충돌 처리.
- 현재 CI: 백엔드 계약·PostgreSQL 동시성·마이그레이션, 프론트 빌드·lint·단위 테스트, Spring 계약과 브라우저 검증.

위 항목은 존재 여부를 코드에서 확인했다. 이번 실행에서 전체 런타임 정상 동작까지 재검증한 것은 아니다. 특히 README의 “Outbox 이후 전달 구간은 남아 있다”는 설명은 현재 `backend/app/services/node_events.py`와 맞춰 갱신해야 한다.

## 3. 발견 사항과 우선순위

P0는 원격 반영 전에 반드시 해결할 항목, P1은 이번 주 핵심, P2는 측정과 사용자 경험 개선이다. 취약점의 공식 심각도와 이 프로젝트의 작업 우선순위는 별개다.

| P1 | P2 · 대형 그래프 조회 비용 | `node_service.py:174`에서 전체 노드 조회. `useNodeEvents.ts:22,55`에서 이벤트 후 재조회와 30초 주기 재조회, `useGraphData.ts:37`에서 노드+태그 동시 전체 조회 | 1천/5천 노드 기준 재조회·응답 크기·렌더 측정 후 중복 요청과 불필요한 렌더만 개선. 현재 느리다는 측정 결과는 없음 |

S2 근거: [Starlette 공식 보안 공지](https://github.com/Kludex/starlette/security/advisories/GHSA-2c2j-9gv5-cj73). 큰 multipart 파일 파싱 중 이벤트 루프를 막을 수 있는 문제이며 공지의 패치 버전은 0.47.2다. 이 버전이 다른 모든 취약점까지 해결한다는 뜻은 아니므로, 적용 버전은 작업 시 전체 감사와 FastAPI 호환성 검증으로 정한다. 로그인은 form 파싱을 사용하므로 해당 경로를 우선 확인한다. JSON 백업은 별도의 raw body 처리다.

JWT의 localStorage 저장은 확인했지만 실제 XSS는 발견·재현하지 않았다. HttpOnly 쿠키 전환은 CSRF·배포 origin·Spring 인증 계약을 함께 바꾸는 작업이므로 이번 주 필수 범위에 넣지 않는다.

## 5. 구체적인 신규 기능 범위

### 연결·저장 상태와 재시도

- 사용자가 노드를 수정한 뒤 서버 응답을 받기 전에는 “저장 중”, 성공 이후에만 “저장 완료”.
- 통신 실패는 “저장 실패 · 다시 시도”. 실패한 입력을 유지하고 프로젝트가 바뀌면 해당 화면의 작업과 분리한다.
- 버전 충돌은 충돌 사실을 알리고 최신 상태를 불러온다. 다른 사용자의 변경을 자동으로 덮어쓰지 않는다.
- WebSocket 연결이 끊기면 재연결 상태를 보여준다. 401/403은 일반 재시도와 구별한다.
- 오프라인 쓰기 큐나 자동 병합은 이번 주 범위 밖이다.

### 프로젝트 찾기

- 현재 계정의 프로젝트 목록에서 이름 검색, 이름순/생성일순 정렬.
- 이번 주에는 받은 목록을 필터링하므로 DB 스키마 변경이 없다. 프로젝트 수가 커질 때 서버 검색/페이지네이션은 별도로 설계한다.
- 멤버 초대·설정 UI는 이미 미커밋 구현이 있으므로 신규 기능 실적으로 중복 계산하지 않는다.

## 6. 인수 조건과 안전한 검증

1. 전용 `brainnet-next-validation` / `brainnet_test`만 사용한다. 개인 DB·기존 볼륨을 초기화하지 않는다.
2. 백엔드 계약 테스트와 PostgreSQL 초대·동시 가입·노드 동시성 회귀를 통과한다.
3. 프론트 단위 테스트, lint, production build 및 Chromium E2E를 통과한다. 초대, 세션 만료, 통신 오류, 저장 실패, 프로젝트 이동을 포함한다.
4. 백업 → 새 프로젝트로 복원 → 내용 비교, 빈 테스트 DB의 Alembic upgrade/downgrade/upgrade를 검증한다.
5. 공통 JWT/요청 계약 변경에 대한 FastAPI·Spring 차등 검증과 이벤트 전달 검증을 유지한다.
6. 브라우저에서 실제 오류 문구·상태 전환·재시도를 확인한다. 코드 테스트만으로 화면 검증을 대신하지 않는다.
7. 의존성 감사는 프론트와 Python/Spring을 구분한다. 패키지 감사 0건을 전체 애플리케이션 보안 보증으로 표현하지 않는다.
8. 결과 보고에는 기준 SHA, 변경 파일, 통과/실패/미실시 항목, 남은 위험, 원격 반영 여부를 기록한다.
