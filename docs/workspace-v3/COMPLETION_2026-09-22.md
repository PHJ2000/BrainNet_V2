# Workspace V3 후속 범위 구현 기록

기준 브랜치 `feat/brainnet-workspace-v3`, 이전 배포 `9560bfe`. 마이그레이션 `b922003`.
앞선 릴리스에서 후속으로 남겼던 제품 기능을 실제 API·화면·복원 계약까지 연결한다.

## 팀 협업과 실행

토론에 답글을 작성하고 현재 멤버를 명시적으로 선택해 알림을 보낸다. 토론 작성자도 답글 알림을 받지만 자기 자신에게는 보내지 않는다.
동일 답글 UUID를 다시 보내도 답글과 알림은 한 번만 생성된다. 알림은 본인만 읽고 표시하며 멤버십이 없어진 프로젝트는 목록에서 숨긴다.
알림 링크는 해당 프로젝트의 해당 토론을 연다. 오래된 토론도 전체 목록의 첫 페이지에 의존하지 않는다.

과제에 최대 50개의 선행 과제를 지정한다. 같은 프로젝트에서만 연결하며 순환·자기 참조를 거절한다.
선행 과제를 완료해야 후속 과제를 완료할 수 있고, 완료된 후속 과제가 남아 있으면 선행 과제를 다시 열 수 없다.
최대 100개 상태 변경은 버전을 모두 확인하는 단일 트랜잭션이다. 하나라도 충돌하면 전체 변경을 취소한다.
검색과 담당자/우선순위 필터는 DB에서 적용하므로 아직 화면에 불러오지 않은 과제도 검색된다.

## 지식과 복구

같은 프로젝트의 두 노드를 설명과 함께 연결한다. 양쪽에서 참조/역참조를 읽고 편집자가 해제할 수 있다.
노드당 발신 링크는 100개이며 목록은 페이지로 읽는다. PostgreSQL `pg_trgm`의 GIN 인덱스를 노드 본문과 과제 제목에 추가한다.

기존 브라우저 초안과 별도로 서버 사본을 개인별로 보관한다. 저장·불러오기·삭제는 사용자가 명시적으로 선택한다.
로컬 입력이 있을 때 서버 사본으로 덮어쓰지 않는다. 동시 수정은 버전 충돌로 거절한다.
삭제해도 내용 없는 버전 기록을 유지해 오래된 기기가 새 초안을 덮어쓰는 문제를 막는다.

v2 백업에 선택 필드인 답글·지식 링크·선행 조건을 추가했다. 구 v2 파일의 복원 요청 해시 계약도 유지한다.
새 프로젝트로 복원하므로 계정·멤버십·멘션 대상·알림·초안·AI 한도는 연결하지 않는다. 대기/실행 중 AI 기록은 INTERRUPTED로 복원한다.

## AI 요청 수명

화면은 `enqueue=true`로 요청을 저장하고 즉시 대기 기록을 받는다. API 연결 종료와 무관하게 DB 대기열을 처리한다.
API 인스턴스의 worker는 프로젝트 잠금과 skip-locked claim을 사용한다. 프로젝트마다 동시에 하나만 실행한다.
대기열은 프로젝트당 5개, 기본 요청 한도는 최근 24시간 20개다. 소유자는 0–100개와 입력 크기 100–16,000자를 설정한다.
이는 요청 소비량 제한이며 통화 단위 청구 상한은 아니다. 모델 가격을 추정해 실제 요금처럼 표시하지 않는다.

대기 요청은 서버 재시작 뒤 이어지고, 결과가 불확실한 실행 요청은 90초 후 INTERRUPTED로 남겨 자동 재호출하지 않는다.
요청자 또는 소유자가 취소할 수 있다. 취소 후 늦게 도착한 응답은 기록에 반영하지 않는다. 이미 전송된 제공자 호출의 청구는 취소되지 않을 수 있다.
실행 전·결과 저장 시 권한을 확인한다. 오류 로그에 원문·제공자 출력은 남기지 않는다.
완료된 결과 두 개를 원문 버전·요청과 함께 비교하고 검토한 하나를 과제로 채택한다.
기존 동기 API 계약은 유지하지만 새 화면은 대기열 경로를 사용한다.

## 검증과 배포

- 전체 백엔드 166개 통과(131.18초), 이후 서버 초안 삭제/재생성 충돌과 구 v2 영수증 회귀 검사 통과. 고유 테스트 총 167개.
- 추가 PostgreSQL 시나리오 8개는 권한·충돌·취소·중복·백업 경계를 다룬다.
- 프런트 단위 14개, TypeScript·ESLint·새 Python 파일 Ruff 통과.
- 전용 빈 PostgreSQL에서 head → b922002 → head 및 Alembic check 통과.
- 1만 과제 + 1만 노드의 로컬 순차 ASGI 검색: 각 20회, 과제 p95 51.90ms, 지식 p95 38.18ms. 최초 요청 포함 최대값은 각각 4.88초, 1.28초다. 이 규모에서 PostgreSQL은 순차 스캔을 선택했다. 고부하·외부 네트워크 성능을 의미하지 않는다.
- 브라우저·최종 배포 결과는 완료 후 이 절에 확정 기록한다.

AI worker의 마지막 정상 poll·실행 여부·누적 실패는 `/health/ai`로 확인한다. `/metrics`에 worker 준비 상태와 실패 횟수를 노출한다.

## 운영 관찰

개인 로컬 배포에는 유료 제공자 키가 없고 AI 생성 버튼은 비활성화된다. 큐·취소·비교는 전용 검증 스택의 mock 제공자로 시험한다.
실제 제공자의 품질·청구 금액, 사람의 스크린리더 사용 경험, 수주간 사용 피드백은 자동 검사 통과와 구분한다.
마이그레이션의 GIN 인덱스 생성에는 테이블 잠금과 추가 디스크가 필요하다. 현재 개인 데이터 규모에서 배포하며 대규모 운영 DB라면 별도 유지보수 창이 필요하다.
