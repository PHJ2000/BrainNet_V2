# Workspace V3 구현 및 검증 기록

기준 `73f2a33`, 브랜치 `feat/brainnet-workspace-v3`. [12주 계획](ROADMAP.md)의 첫 통합 릴리스와 추가 복구 묶음이다.
3개월 운영이나 전체 로드맵을 완료한 기록은 아니다.

## 구현한 사용자 흐름

- 프로젝트 안에서 아이디어 맵 / 실행 보드 / 지식 / 토론 / AI 검토 / 활동으로 이동한다. 모바일에서는 프로젝트 메뉴가 접힌다.
- 지식 검색은 참여 중이며 삭제되지 않은 프로젝트만 반환한다. `%`, `_`는 문자 그대로 검색한다. 개인 북마크와 저장 검색은 사용자별로 격리된다.
- 노드를 과제로 연결한다. 제목·완료 조건·상태·우선순위·담당자·마감일을 편집한다. 상태별 보드와 제목/담당자/우선순위 필터를 제공한다.
- 토론은 노드 연결, 작성자 편집, 작성자 또는 소유자 해결, 버전 충돌 검사를 지원한다. 답글과 멘션은 후속 범위다.
- AI 검토는 선택 노드 최대 8개로 아이디어 확장/요약/실행 제안을 요청한다. 원문과 결과를 저장하고, 원본 변경 여부를 확인한 뒤 과제로 한 번만 채택한다.
- 소유자는 휴지통에서 프로젝트를 복원한다. 삭제/복원은 예전 미사용 초대 코드를 살려내지 않는다.
- schema v2는 그래프·과제·토론·AI 기록·내 북마크를 같은 DB 스냅샷에서 내보낸다. 파일 미리보기와 새 프로젝트 복원이 가능하며 v1도 계속 지원한다.
- 과제·토론 초안과 생성 요청 ID를 계정/프로젝트/탭별 브라우저 저장소에 보관한다. 저장 응답 유실 후 새로고침해도 동일 요청으로 이어갈 수 있다.
- 개인 템플릿은 현재 작업 내용의 사본이다. 원본 변경과 독립적이며 새 프로젝트로 생성한다. 개인 저장 검색도 서버에 보관한다.

## 데이터와 권한

마이그레이션 `b922001`(과제, 토론, 북마크, AI 기록, 활동)과 `b922002`(개인 검색/템플릿)를 추가했다.
과제·토론은 노드 삭제 시 연결만 해제한다. 담당자는 현재 프로젝트의 소유자/편집자만 지정할 수 있다.
새 공유 데이터 쓰기는 프로젝트 행 잠금 후 권한을 확인해 멤버 권한 변경과 직렬화한다. 과제·토론 변경은 기대 버전을 검사한다.
과제·토론 생성은 UUID와 요청 해시를 함께 검사해 재시도 중복 생성을 막는다. UI는 실패한 생성 내용과 UUID를 보존한다.
변경 알림은 기존 transactional outbox와 WebSocket을 통해 목록을 다시 읽게 한다.
프로젝트 설정 저장 응답에서 현재 역할과 AI 설정이 빠져 화면 권한이 달라질 수 있던 부분도 수정했다.

AI 요청당 노드 4,000자, 총 16,000자, 결과 12,000자 제한. 프로젝트별 동시 1건, 최근 24시간 20건.
DB 트랜잭션을 반환한 뒤 제공자를 호출하며 전체 호출 상한은 45초다. 서버 중단으로 남은 RUNNING 기록은 60초 뒤 INTERRUPTED로 보인다.
이 버전은 요청 처리 방식이며 자동 재개하는 작업 큐가 아니다. 동일 요청을 다시 보내도 제공자를 다시 호출하지 않는다.
실제 유료 제공자 키 없는 로컬 기본 배포에서는 AI 요청 버튼이 비활성화된다. 테스트는 로컬 mock 제공자와 대체 함수로 수행했다.

백업 v2는 10 MiB / 노드 5,000 / 과제 1,000 / 토론 2,000 / AI 기록 500 상한이다.
JSON 복원은 계정·권한·담당자·투표·활동 이력을 복원하지 않으며, 새 프로젝트의 작성자는 복원한 계정으로 지정한다.
개인 템플릿과 저장 검색은 프로젝트 파일에 포함하지 않는다. 템플릿은 최대 1 MiB, 검색/템플릿은 각각 30개다.
전체 DB 복구에는 SQL 백업을 사용한다. 브라우저 초안은 서버 백업에 포함되지 않는다.

## 확인한 결과

- 백엔드 전체 159개 통과, 새 실제 PostgreSQL 시나리오 11개 포함. 최종 전체 실행 93.19초.
- 프런트엔드 단위 14개, TypeScript 검사와 ESLint 통과.
- 마이그레이션 새 전용 DB에서 head → b822001 → head, Alembic metadata check 통과.
- 브라우저 신규 2개 시나리오 통과. 과제/토론/북마크/AI 채택과 모바일 390px 화면 확인.
- 저장 성공 후 응답만 유실시키고 새로고침→초안 재개→재시도했을 때 과제가 1개만 남는 것 확인.
- v2 파일 다운로드→미리보기→새 프로젝트 복원, 템플릿 생성, 저장 검색 확인.
- 초기 브라우저 실패 원인은 테스트 Nginx에서 `/workspace` API 경로가 프런트엔드로 전달되던 설정 누락이었다. 경로를 추가하고 재검증했다.
- 기존 브라우저 회귀 21개와 신규 2개, 총 23개 시나리오 통과. 확장 성능/장애 시나리오 3개는 실행하지 않았다.
- 기존 대시보드 fixture 두 곳에 새 개인 템플릿 API 모의 응답이 없어 테스트 토큰이 실제 API에서 거절되는 문제가 있었다. fixture를 보완하고 실패한 2개만 재실행해 1.5초에 통과했다.
- 기존 1,000노드 화면 검사에서 검색 p95 28.3ms, 접기 p95 67.6ms. 고정 fixture의 로컬 측정이며 대규모 운영 성능 보장은 아니다.
- offline migration SQL 렌더링, Ruff, git diff whitespace 검사 통과.

## 배포 전 보존

개인 DB를 `.tools/local-before-workspace-v3.sql`로 백업했다. 파일과 `.env.local`은 Git에 포함하지 않는다.
배포 전 개인 데이터: 프로젝트 1개, 노드 2개. 노드/프로젝트/멤버 전체 행 해시를 `.tools/local-before-workspace-v3.json`에 저장했다.
최종 배포 및 원격 상태는 검증 후 아래에 추가한다.

## 남은 로드맵

내구성 있는 AI 작업 큐·취소·여러 결과 비교, 답글·멘션·알림함, 양방향 지식 링크,
과제 의존성·일괄 편집, 서버 동기화 초안, 큰 데이터의 전체 서버 필터/검색 인덱스,
키보드/스크린리더 심화 검증과 수주간의 실사용 관찰은 후속 작업이다.
현재 보드 필터는 불러온 과제에 적용하며 이전 과제는 페이지로 더 불러온다. 장시간 부하와 실제 AI 품질 검증은 수행하지 않았다.
