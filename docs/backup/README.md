# 로컬 프로젝트 파일 사용 안내

프로젝트 화면의 **파일**에서 Markdown과 JSON을 내려받는다. 대시보드 또는 파일 패널의 **JSON 백업 가져오기**는 파일 검증 → 제외 항목과 건수 확인 → **새 프로젝트 생성 확인** → 복원 결과 순서로 동작한다. 유료 API와 외부 서버를 사용하지 않는다.

## Markdown

- 전체 프로젝트 또는 명시적으로 고른 가지와 모든 자손을 내보낸다. 검색/태그 필터/접기는 출력 범위를 바꾸지 않는다.
- 기본 ACTIVE. `GHOST·ARCHIVED 포함`을 선택하면 세 상태 모두 포함한다. 제외된 조상은 ID/부모/상태/태그만 남긴 맥락 항목이다.
- 형제 순서는 `(order_index, id)`. 실제 부모 관계로 깊이를 계산한다. 제목은 최대 6단계, 이후 중첩 목록으로 이어진다.
- 원문은 `text` 코드 블록에 그대로 넣는다. 원문의 가장 긴 backtick보다 긴 fence를 사용한다. HTML, 링크, 원문 Markdown은 실행/해석되지 않는 텍스트로 보존된다. 깊은 목록에서는 각 줄에 목록 들여쓰기가 추가된다.
- 파일명은 Windows 예약 문자/장치 이름을 정규화한다. UTF-8 `.md` 파일이며 복원용 형식은 아니다.

## JSON v1

[JSON Schema](project-backup-v1.schema.json)와 [예제](example-v1.json)가 런타임 검증 모델과 함께 제공된다. `PYTHONPATH=backend python backend/scripts/export_backup_schema.py`로 재생성한다.

포함: 이름/설명, 본문, 모든 노드 상태, 부모 관계, 깊이, 형제 순서, 좌표(null 포함), 태그 이름/색상, 노드-태그 연결.

제외: 계정, 암호/JWT/API 키, 멤버십/초대/권한, 투표, 메트릭, 변경 기록, Outbox, 진행 중 요청. 작성자 개인정보와 DB PK도 파일에 싣지 않는다. 복원 소유자와 노드 작성자는 가져온 사용자이며 version은 0으로 시작한다.

- 파일 내부 `ref`를 새 DB ID로 매핑한다. 루트 자동 생성 API를 거치지 않으므로 중복 루트가 생기지 않는다.
- `schema_version`은 정수 1만 지원한다. 알 수 없는 필드/중복 JSON 키/참조 중복/유실 관계/순환/잘못된 상태/비유한 좌표/NUL/불완전한 Unicode surrogate는 오류 경로와 함께 거부한다.
- 루트의 깊이는 0, 자식은 부모 깊이 + 1이다. 비어 있지 않은 유효 그래프에는 루트가 있으며 ACTIVE 루트는 최대 하나다. GHOST/ARCHIVED 루트 여러 개는 기존 DB 계약상 가능하다.
- `order_index`는 0부터 PostgreSQL int 최대값까지, 동률은 허용한다. 형제 순서는 ID로 결정한다.
- **기존 데이터의 깊이 값이 부모 관계와 다르면** 원본 DB를 바꾸지 않고 파일의 `depth_adjustments`에 변경 전/후 값을 기록한다. 복원 미리보기에 해당 목록을 보여준다. JSON 파일 자체에 잘못된 깊이가 있으면 자동 수정하지 않고 거부한다.
- 상한: UTF-8 파일 **10 MiB**, 노드 **5,000개**, 태그 **5,000개**, 연결 **50,000개**, 실제 깊이 **100**. 프로젝트 이름 120자, 태그 이름 80자/색상 7자는 DB 길이와 같다. 파일 크기는 UI 파일 읽기 전과 서버 JSON 파싱 전에 검사한다. 프록시도 10 MiB로 제한한다.
- 파일 내 URL을 요청하거나 명령을 실행하지 않는다. 새 프로젝트 전체와 요청 영수증을 한 트랜잭션으로 저장한다. 실패 시 기존 프로젝트와 부분 생성 데이터는 남지 않는다. PostgreSQL 시퀀스 번호의 빈 값은 롤백 대상이 아니다.
- 같은 파일의 처리 응답을 놓치면 파일을 다시 선택한다. 사용자/파일 해시별 요청 키를 브라우저에 저장하여 새로고침 후에도 결과를 재사용한다. 성공 확인 후 같은 파일을 의도적으로 다시 가져오면 새 프로젝트를 만든다.
- 키 재사용을 막는 작은 영수증은 계정 삭제까지 보존한다. 복원 결과를 삭제한 뒤 옛 요청을 다시 보내면 410으로 거부하며 또 만들지 않는다. 작업 성공을 확인하기 전 브라우저 저장소를 지우지 않는다.

## DB 백업과의 차이

JSON은 프로젝트 자료를 다른 설치로 옮기는 파일이다. `.env.local`은 로컬 인증/DB 연결 비밀값이며 JSON에 들어 있지 않는다. `brainnet-local_local-db` 볼륨은 계정/변경 이력을 포함한 실제 DB 저장소다. 전체 환경을 보존하려면 DB 덤프/볼륨과 `.env.local`을 별도로 보관한다. `docker compose down -v`로 이 볼륨을 지우면 JSON에 없는 정보는 복구되지 않는다.

## 일관성과 권한

두 내보내기는 동일한 PostgreSQL `REPEATABLE READ`, 읽기 전용 트랜잭션으로 권한과 노드/태그를 읽는다. 실행 도중 다른 사용자가 변경하더라도 한 응답에 여러 시점의 관계가 섞이지 않는다. 다음 요청부터는 회수된 멤버십을 다시 확인한다. 끊긴 다운로드/권한 오류를 빈 파일 성공으로 처리하지 않는다.
